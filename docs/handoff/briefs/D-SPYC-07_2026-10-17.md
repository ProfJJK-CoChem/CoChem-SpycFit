### Question
When a parameter change moves an assigned transition's label onto a different eigenstate, or changes the eigenvector behind a kept label, what should the native model do, and should SpycFit check finished SPFIT and DPFIT runs for the same event?

### Why it matters now
Lines are at `80ecfa2`.
- SF-HAM-002 is "proposed; blocked on D-SPYC-07" (`docs/srs/CoChem-SpycFit_SRS_v2.md` l.738-741); the V-HAM row reads "label swaps halt" (l.1508); the `model` row names it (`docs/architecture/CoChem-SpycFit_Architecture.md` l.55). WP-HAM's "Wang-block labelling" item (`docs/plan/CoChem-SpycFit_Plan.md` l.33-35) depends on it, though the plan does not name D-SPYC-07.
- It applies because a native model exists (`docs/handoff/PI_DECISIONS.md` l.185; `docs/decisions/D-SPYC-18.md` l.22-23). Errata row 14 covers SPFIT relabelling only "Without that model" (`docs/handoff/REVIEW_ERRATA.md` l.28); no requirement covers it inside an SPFIT run (SF-CMP-004a-d, l.1099-1114).
- The PI stated on 2026-10-17 that SPYFY's value is to "utilize GPU to parallel, array, and make fitting and calculations dynamic recalculate on the fly" (`docs/decisions/D-SPYC-04.md` l.25-28; SRS l.131-135), so the rule must hold for batched evaluations under any R1 engine. Conflict, unresolved here: the Method Matrix says JAX and the GPU "are **not** used to replace SPFIT" (`CoChem-BASE/Method_Matrix.md` l.3632); D-SPYC-04.md l.58-64 requires R1 to state it.

### Context
- **SPFIT/SPCAT reference** (JPL sources, `docs/handoff/calpgm_sources_2026-10-11.sha256`). DIAG 0 (default: `spinv.c` l.2288, l.2338) calls `ordblk` (l.563-565): "block projection matrix ... dominant diagonal and energies ... ordered within block" (`ulib.c` l.33-35). DIAG 1-5 (projection sort of the full block, `ordham`/`fixham`, v-block projection) also exist (`spinv.c` l.567-600); none compares labels between parameter sets. SF-CMP-004b requires recording each engine's rule, not reproducing it, so the native model need not implement DIAG 1-5. SPFIT maps each line to block and index once (`calfit.c` l.318), reapplies DIAG every iteration (l.379; l.347-656) and never compares labels between iterations.
- **Detection in Pickett output.** SPCAT prints PMIX per `.egy` line (`calcat.c` l.528-530) and eigenvectors at EGYFLG ≥ 3 (l.207, l.552-557). Scratch copy of the manifest HCO files (FLAGS 112→113; SPCAT `8d3eb357…`): 100 states, 8 with PMIX < 0.9, lowest 0.795666 for the two 1₀₁ levels of block 4, 0.015258 cm⁻¹ apart in different spin sub-blocks. Mixing, not a swap; HCO is open-shell (errata l.33). IBLK/INDX matching SPFIT's line mapping: UNVERIFIED.
- **P1 swap rate: no evidence.** The within-sub-block case is untested agent reasoning; swaps are expected with hyperfine, spin, multi-state and LAM terms (P2-P4, SRS l.173-175). Proposed V-HAM-03 test, not yet run: on scratch copies of the SO₂ and H₂CO panel inputs (§8.3, l.1535-1536), step each fitted constant through ±3u in ten steps and count swaps and near ties, measuring how often A would halt.
- **2026-10-17 answers.** HPC is headless (SF-UI-007, l.903-905). BASE owns durable task state (SRS l.205; TORQ D08, `CoChem-TORQ/docs/wiki/review/Decisions_and_Risks.md` l.87); SpycFit's run outcomes (l.69) include no halt. Native catalogs carry their producer (D-SPYC-16); swap flags travel in provenance; state identity includes the electronic-state field (SF-CMP-004e, l.1102). Previews are not stored as results (SF-UI-004, l.857-858); SF-WIN-001 (l.1043) has no storage rule. Forward prediction is gated by SF-HAM-001 alone (l.1339-1340; D-SPYC-14).

### Options
- **A (sheet, 2026-10-11).** "Halt the fit and show the swap" (`PI_DECISIONS.md` l.193).
  - Pros: nothing proceeds on a changed state.
  - Cons: "show the swap" has no headless form unless the halt is a recorded state (SF-UI-007); SPFIT never halts, so near-crossing comparison stays INCOMPLETE.
  - Risks: frequent stops in P2-P4; P1 rate unknown until the stepping test.
- **B (sheet).** Warn and continue.
  - Pros: same behaviour as SPFIT.
  - Cons: no export gate; a fitted line may refer to a state the expert did not assign.
  - Risks: wrong residuals reach export.
- **C (new).** Halt stored native fits; previews continue with the swap shown.
  - Pros: stricter than D for kept results.
  - Cons: native and SPFIT differ; replicates in unattended fits (SF-FIT-005a, SF-FIT-018, SF-INF-003, UC-7) are counted, not halted.
  - Risks: the halt form below is a joint BASE question (`AGENTS.md` l.18).
- **D (new).** Flag every swap, continue, record it in provenance; export needs an expert-review record (SF-CMP-015b, l.1268-1269).
  - Pros: the PI's divergence pattern ("Exploration continues, but publication export requires explicit expert review", `docs/HANDOFF.md` l.27; amendment l.87), by analogy; identical for native, SPFIT, batched and headless runs.
  - Cons: a stored native fit can rest on an unreviewed swap until export.
  - Risks: flags ignored if not prominent.
- **E (labelling variant, any letter).** Label by eigenvector-overlap continuity and propose the relabel for expert acceptance (Western, doi:10.1016/j.jqsrt.2016.04.010 §2.2; `docs/wiki/review/CoChem-SpycFit_SRS_Review.md` l.435).
  - Pros: stable labels near crossings.
  - Cons: energies (SF-HAM-001) are unchanged, but a label names a different level; SF-CMP-004a rank matching needs a declared native-to-DIAG mapping (SF-CMP-004b).
  - Risks: two labelling rules in one comparison.

**Halt form for A and C (agent proposal).** Run outcome `HALTED_LABEL_SWAP` (SF-RUN-004a, l.1430), returned to BASE through the handoff (§4.4); the expert accepts or rejects the relabel through the headless API (SF-API-001, l.587-588); the SPFIT run of record (plan l.36-37) continues separately.

**Provenance fields for D (agent proposal).** Per transition: swap flag, largest overlap, parameter step, old and new labels, reviewer action and time. 07c's near-tie flag uses SF-CMP-004c's ambiguity field with its own reason code, since SF-CMP-004c concerns frequency candidates inside the tolerance (l.1109-1110).

**07b (any letter).** Post-run check of SPFIT/DPFIT (same `ordblk`, `dpi.c` l.401): compare SPCAT/DPCAT eigenvectors (EGYFLG 3) at start and final parameters; two extra SPCAT runs per fit, 0.006-0.020 s wall each on HCO (scratch copy, Xeon 2.10 GHz; larger blocks UNVERIFIED). INCOMPLETE when a `.lin` state lies outside FBGN/FEND/MAXV or the basis changed; misses swaps that reverse mid-run. Default needs a PI-named value (`AGENTS.md`); candidate: on, user-overridable, recorded.

**07c.** Swap test: the largest-overlap map |⟨old_i|new_j⟩|² is not the identity for a state an assigned line uses (two states: < 0.5). Candidate margin: largest overlap below 0.9 flags a near tie; 0.5 is the two-state crossover, and 0.9 flags HCO's block-4 pair (0.796) and seven other states. No published value found (agent proposal, outside SF-CMP-008a's tiers, l.1132-1137).

### Agent recommendation
D, with 07b on by default and 07c at 0.5/0.9, tested on an analytical two-state crossing, HCO stepped across block 4 and the SO₂/H₂CO stepping. D follows the PI's divergence rule, treats native, SPFIT, batched and headless runs alike, and fits on-the-fly array evaluation, where "between iterations" has no single meaning. Main risk: a swap flag nobody sees before a result is reused. Reduce it by recording every swap in provenance, marking the comparison INCOMPLETE until reviewed and showing the flag in the comparison view (SF-CMP-014a, l.1257).
