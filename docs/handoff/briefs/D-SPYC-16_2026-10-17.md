### Question
Where is the line between the rotational catalogs TORQ produces and those SpycFit produces, and should the two modules share one SPCAT runner and one catalog-equivalence test?

### Options
- **A (sheet). Split by origin: TORQ from computed constants, SpycFit from fitted or edited ones; one shared test.**
  - Pros: One catalog per computed set; TORQ's calibrated uncertainties kept.
  - Cons: Conflicts with SF-IF-005a and the forward and informed stages.
  - Risks: SpycFit cannot set spin weights or Q in catalogs it compares.
- **B (sheet). SpycFit makes all catalogs; TORQ exports constants only.**
  - Pros: One catalog code path.
  - Cons: Removes TORQ-SPEC-001's catalog stage; TORQ depends on SpycFit.
  - Risks: Reopens D12 and TORQ's V-SPCAT evidence.
- **D (new). Split by producer.** TORQ owns catalogs from its computed constants; SpycFit owns every catalog it makes, from any constants, labelled with their origin. Consumed TORQ, BASE and user catalogs keep their producer label (SF-IF-005c); BASE runner output never counts as SPCAT output. One shared test and parameter-ID/sign table.
  - Pros: Agent reading: keeps TORQ's computed-constant stage. Needs no TORQ exporter.
  - Cons: TORQ's `experimental_fit` path and this reading of D12 need the TORQ maintainer's view. Catalogs from the same constants can differ in spin weights, Q and uncertainties; the SRS must say which sets assignment windows.
  - Risks: Pickett adapters drift apart, as BASE's deck already has.
- **E (new). As D, plus one shared runner and receipt (in BASE, or TORQ's backend extended).**
  - Pros: One deck writer; least drift.
  - Cons: TORQ's contract must grow before P2/P3.
  - Risks: SpycFit profiles wait on BASE or TORQ releases.

### Agent recommendation
D now; revisit E once BASE's build mechanism exists. D satisfies SF-CMP-001a and SF-IF-005a, keeps TORQ's computed-constant stage and does not wait for TORQ's exporter. The main risk is adapter drift; reduce it with one shared test. Its fixtures are downloaded and SHA-256-checked (SF-DATA-001e, l.560-563), never committed (`AGENTS.md` l.95-97), for example D-SPYC-14 panel files after reuse checks (`docs/HANDOFF.md` l.77). It compares `.cat`, `.egy` and `.str` byte for byte on one binary, `.cat` and `.egy` within T1 (SF-CMP-008b) across builds, and `.out` only between same-source builds, which tabulate the same temperatures. Each TORQ change needs a specific PI request and the TORQ maintainer's agreement.
