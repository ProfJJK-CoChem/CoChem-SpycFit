### Question
Which source and owner should SpycFit use for isotope masses, abundances and constants, and which defaults apply when an input omits them?

### Why it matters now
- SRS v2 §1.7.5 and SF-IO-005 are blocked on it (`docs/srs/CoChem-SpycFit_SRS_v2.md` lines 309-313, 572-575, at `fadb028`); both get rewritten to match.
- Masses set the isotopologue constants sent to GEOM (`docs/decisions/D-SPYC-10.md`); abundances and constants set intensities (SF-INT-001a).
- It must fit D-SPYC-19 (TORQ is a dependency, PI 2026-10-17). It sets Phase 2 pins and Phase 3 provenance (`docs/plan/CoChem-SpycFit_Plan.md` lines 16-17).

### Context
- **Sources.** In AME2020, 1,008 of 3,558 masses are estimates marked "#" (doi:10.1088/1674-1137/abddaf). CIAAW 2024 gives intervals, not values, for H, C, O, S, Cl, Br and Ar (⁴⁰Ar [0.936, 1.000]), with no reuse terms (https://www.ciaaw.org/isotopic-abundances.htm). CODATA 2022: doi:10.1103/RevModPhys.97.025002.
- **mendeleev (MIT) supplies masses in TORQ, BASE, TOPOS and GEOM** (their `pyproject.toml` lines 22, 21, 16; `cochem-geom/Stage 1.1 Ingestion Math.md` line 12). Agent check: mendeleev 1.0.0 and 1.3.0 match AME2020 for all 3,557 masses and uncertainties, including the 1,008 unflagged estimates (none natural). Its abundances are CIAAW 2013 values, intervals as midpoints, via NUBASE2020. Its file hash changes between releases; masses do not.
- **TORQ.** `cochem_torq.units` builds `cochem.constants.codata-2022-torq-compatible/1` from SciPy and refuses other editions (`src/cochem_torq/units.py` lines 25, 51-56). `isotope_record` returns no abundance and records a most-abundant default (`Libraries/cochem_isotopes.py` lines 35-43, 69-85).
- **BASE** ships a different `cochem_torq` without these modules and does not depend on CoChem-TORQ (`CoChem-BASE/pyproject.toml` lines 14-38, 70, 78). The TORQ wheel overlaps it on `cochem_torq`, `cochem` and `Libraries`. D-SPYC-19's note (line 31) that BASE supplies TORQ therefore fails (cross-repository problem).
- **h/(8π² u Å²) is typed in** by BASE (`src/cochem/core/cochem_constants.py` line 18) and eight SpycFit modules; one "exact" SpycFit value matches neither CODATA 2018 nor 2022 (`cochem_jensen_averager.py` line 100).
- **Effect sizes** (agent calculations): CODATA 2018→2022, 1.4×10⁻⁹ (through u); SPCAT's built-in hc/k and intensity prefactor (JPL calpgm `calcat.c` lines 97, 175), 2.2×10⁻⁶ and 1.7×10⁻⁵; nuclear masses, 2.3-5.4×10⁻⁴ (H to I); atomic weights, which ORCA uses by default (https://www.faccts.de/docs/orca/6.1/manual/contents/structurereactivity/frequencies.html), 9.2×10⁻⁴ for carbon.
- **The 2026-10-11 recommendation fits in part** (`PI_DECISIONS.md` line 101): atomic masses, CODATA 2022 and a derived h/(8π²) still fit. It omits abundances, SPCAT built-ins, input-carried masses and PES refinement (SF-SCOPE-005), whose masses can differ (doi:10.1080/00268970701604671), so "never nuclear masses" (`AGENT_HANDOFF.md` line 101) is too absolute.

### Options
Common rules: atomic masses for isotopologue constants, including those in Pickett files; nuclear or effective masses only as stated model inputs; values arriving with an input (TORQ, ORCA, JPL, CDMS, HITRAN) recorded as received, never silently recomputed; SPCAT built-ins recorded. No option changes a mass value.

**A (sheet A). Call TORQ's `units` profile and `isotope_record` at run time.**
- Pros: one implementation; TORQ is already a dependency.
- Cons: no AME2020 label, estimated flag or abundances.
- Risks: fails while the BASE-TORQ overlap is unresolved.

**B (sheet B). A SpycFit-owned snapshot with id and manifest (source, date, SHA-256), checked in CI against mendeleev and SciPy.**
- Pros: AME2020 label, estimated flag; independent of the overlap.
- Cons: a second copy; D-SPYC-19's record lists SpycFit-held constants as not chosen (line 45), though the PI's words omit constants.
- Risks: AME and CIAAW reuse terms UNVERIFIED; nothing committed until confirmed.

**D (new). mendeleev pinned exactly and read directly; constants per sub-question 3.** Provenance: "AME2020 via mendeleev X.Y.Z" and the extracted table's hash. CI checks used isotopes against the hash-pinned AME2020 file (not committed), which also gives the estimated flag.
- Pros: same values as all siblings; no committed data.
- Cons: abundances are CIAAW 2013 values.
- Risks: data changes slip through if the check lapses.

**E (new). Versioned reference data in BASE, or a new shared package.**
- Pros: one profile ecosystem-wide.
- Cons: BASE must add a profile id, edition check and hashes, and drop its silent isotope default (`src/cochem_base/physics/isotopes.py` lines 242-243); all siblings must adopt it; only the PI can ask.
- Risks: SpycFit waits on other repositories.

Sheet option C (AME2020 with CODATA 2018) stays open, not recommended: TORQ implements CODATA 2022.

Sub-questions:
1. Isotope default: (i) most abundant, named, overridable, recorded; (ii) none; the user labels every atom.
2. Abundance: (a) mendeleev's value; (b) CIAAW 2024 midpoint, interval recorded; (c) user value per sample, with (a) or (b) as named default.
3. Constants: (f) CODATA 2022 frozen in SpycFit's profile, SciPy as cross-check; (p) SciPy pinned below the release adopting CODATA 2026, due early 2027 (https://codata.org/fundamental-physical-constants; version UNVERIFIED). Editions change only with TORQ.
4. Nuclear spins and moments (hyperfine, Raman spin weights): here or separate?

### Agent recommendation
D; E later, if the PI asks BASE. D matches every sibling's masses, commits no third-party data and keeps the estimated flag; B adds a copy for a flag no natural isotope needs. Sub-questions: (i); (c) with (a), since a CIAAW 2024 midpoint gives ⁴⁰Ar 96.8 %, not 99.6 %; (f); spins separate. Main risk: a silent data change in a new mendeleev release; exact pins (Phase 2 PR), the AME2020 check and the table hash reduce it.
