## 1. Executive summary

### 1.1 Verdict

The SRS cannot serve as the contract for the audit/fix/replace agent. It must be replaced by an SRS v2 written with the PI before any code is touched. Five reasons, each independently sufficient:

1. **It does not say what SpycFit is.** Four artifacts give four incompatible product definitions (README: IR/Raman/UV-Vis translator; User Manual: PGOPHER front end with `Type = IR|Raman|UVVIS|Microwave`; SRS: air-gapped batch LM engine with NMR and HITRAN chapters; recovered 2026-08-07 plan: CP-FTMW active-learning assigner). The SRS itself asserts a native JAX fitter (l.27, l.1159), an SPFIT/SPCAT seed-and-fit loop (l.599), "SPCAT/SPFIT emulators" (l.1047) and "SPFIT/SPCAT or PGOPHER backend wrappers" (l.1455) without choosing. The governing Method Matrix (l.3632) has already decided: JAX is "not used to replace SPFIT". The SRS never cites the Method Matrix (0 occurrences).
2. **It models an ecosystem that does not exist.** TORQ is defined as a "message broker" behind a hardware-firewalled "data diode" (l.18, l.47, l.55); BASE and TOPOS are never named; a "Genesis" tier is invented; the TORQ-to-SpycFit data contract (TORQ-EXP-004, V-CONSUMER) is never referenced; and the SRS violates its own air-gap and "zero persistent state" clauses in at least seven places (runtime AME fetch l.483, Voila kernel state l.1540, SQLite `job_board` writes l.1780). An agent cannot design an interface against a fictional topology.
3. **Two of ten chapters specify the wrong experiment, and the physics in the rest contains errors that would propagate into every fit.** Chapter 2 is sized for 16-32 GiB protein-NMR tensors; Chapter 8 synthesises HITRAN/ExoMol cross-sections at 296 K with pressure broadening on >10,000 cm^-1 grids. Within the in-scope chapters: nuclear masses (not atomic) are mandated for the inertia tensor (l.484-487, a +0.03 % bias on every prior); the `.lin` parser cannot read a real SPFIT file (l.462); the "total-effect Sobol index" at l.1206 is the complement of the correct quantity, so a literal implementation freezes A, B, C and floats the octic terms; the conformer-rejection gate compares effective constants with equilibrium constants at a 5 % threshold (l.1730-1732); eigenvalue-to-(J, Ka, Kc) labelling, the central step of asymmetric-rotor fitting, is specified nowhere.
4. **It omits the observables that make the Method Matrix system class assignable.** No nuclear quadrupole Hamiltonian or F quantum number (hyperfine has 0 occurrences; four of the Method Matrix's six validation systems are hyperfine-resolved), no user-supplied nuclear-spin weights (the SRS claims to derive them automatically, which the Method Matrix forbids as binding), no inertial defect or planar moments, no multi-state or tunnelling Hamiltonian, no isotopologue or structure workflow, no assignment algorithm (triples search, Loomis-Wood, click-to-assign), no peak picking, no fit uncertainties or correlation matrix, no publication outputs, no benchmark set.
5. **It is not a specification document.** Nine of ten chapters exist twice with divergent normative content and no statement of which binds; eleven blocks of agent chatter are embedded in the body ("I am still waiting for the full audit report", l.423); there are four requirement IDs in 1805 lines while the tests cite forty IDs that exist only in prompt files outside the repository; there is no glossary, no verification method, no traceability, no document control; and the governance claims it makes (locked main, two peer reviews, benchmark CI) are false on inspection (0 PRs, 0 merges, CI runs a single `find`).

### 5.7 Uncertainties, determinability and fit diagnostics (NUM-04, GAPS-03, NUM-02, PHYS-16, CRITIC-01, SCOPE-30, TRACE-10, PHYS-17)

> **SPYC-FIT-001** The fit SHALL minimise chi^2 = sum_i (nu_obs,i - nu_calc,i)^2 / sigma_i^2 with sigma_i from the `.lin`; the residual r_i = nu_obs,i - nu_calc,i and the Jacobian J_ij = d nu_calc,i / d theta_j are defined once in the Conventions section. Exactly one fitter exists in the package.
>
> **SPYC-FIT-002 (outputs)** After convergence SpycFit SHALL report: parameter values with 1 sigma standard errors from diag[(J^T W J)^-1], both unscaled and scaled by sqrt(chi^2_r), formatted value(1 sigma) in the last quoted digits; the full correlation matrix with |rho| > 0.9 pairs flagged; N_lines, N_params, degrees of freedom, weighted RMS sigma_fit = sqrt(chi^2/(N - M)), unweighted RMS in kHz, max |o-c|/sigma; a per-line table of nu_obs, nu_calc, o-c, sigma_i, (o-c)/sigma_i with |o-c|/sigma_i > 3 flagged, in Pickett `.fit` layout; the condition number of J^T W J; the convergence status.
>
> **SPYC-FIT-003 (parameter state)** Every parameter SHALL carry a user-settable state in {fitted, fixed@value with provenance tag in {measured, computed(method), assumed, zero}, constrained(prior mu, sigma)}. The default fit is unregularised weighted least squares; constrained fits are opt-in and their outputs labelled. The system SHALL NOT change a parameter's state automatically. Sensitivity/determinability analysis (SVD of W^1/2 J diag(theta); candidates for fixing when relative uncertainty > 100 % or |rho| > 0.999) is advisory, printed as a recommendation list and logged, never applied silently. All output tables SHALL print the provenance tag of every non-fitted parameter. Source: MM §20.3, §17 exclusion rule.
>
> **SPYC-FIT-004 (LM control)** The SRS SHALL state lambda_0, the lambda update factors (default: divide by 3 on an accepted step, multiply by 2 on a rejected step; Transtrum & Sethna 2012), the acceptance rule, the convergence criterion (|Delta chi^2|/chi^2 < 1e-8 or max |Delta theta_k / sigma_k| < 1e-3), the iteration limit, and the rank-deficiency policy: if J^T W J is rank-deficient at the stated tolerance the fit SHALL stop and name the null-space combination (never silently pseudo-invert).
>
> **SPYC-FIT-005 (Jacobian)** J_ij SHALL equal <psi'|dH/dtheta_j|psi'> - <psi''|dH/dtheta_j|psi''> from the eigenvectors of the forward diagonalisation; dH/dtheta_j is analytic for parameters entering H linearly (A, B, C, distortion, chi, V3) and obtained by forward-mode differentiation of the Hamiltonian builder for non-linear parameters (F, rho); at an exact degeneracy dH/dtheta_j SHALL be diagonalised in the degenerate subspace; no regularisation of the Jacobian is permitted; differentiation through the eigensolver is not required and, if used, SHALL reproduce the above to 1e-10 relative in a unit test. Acceptance: agreement with central finite differences of d nu/d theta to 1e-6 relative on the propylene oxide benchmark including near-degenerate K-doublets.
>
> **SPYC-FIT-006 (signs)** Delta_J > 0 and D_J > 0 are soft bounds with a warning; no other distortion constant is sign-constrained; signs are stated in Watson's convention and converted to SPFIT storage (-Delta_J, -Delta_JK, -Delta_K, -delta_J, -delta_K; -D_J, -D_JK, -D_K, +d1, +d2) at the file boundary.
>
> **SPYC-FIT-007 (labels)** Eigenvalues SHALL be labelled per SPYC-HAM (Wang blocks, energy order, eigenvector overlap under perturbation); any label swap between iterations SHALL be logged (PI decision: halt or warn).

### 8.6 "SpycFit is / is not" scope statement (draft for Chapter 0; decision D-SPYC-01)

> **Definition.** CoChem-SpycFit is the rotational-spectroscopy assignment and fitting workbench of the CoChem ecosystem. It consumes (i) the versioned TORQ spectroscopy bundle (TORQ-EXP-004) containing, per candidate conformer or topology and isotopologue, A_0/B_0/C_0 (or A_e/B_e/C_e with Delta B_vib) labelled with their Method Matrix Product class and [M]/[D]/[E] tag, quartic (and where available sextic) distortion constants with reduction and representation tags, signed dipole components, nuclear quadrupole tensors, inertial defect and planar moments, vibrational-satellite constants and, for large-amplitude systems, barrier, reduced-mass, path and tunnelling estimates; and (ii) a jet-cooled broadband CP-FTMW spectrum (2-22 GHz, extensible to 26 GHz; T_rot 1-2 K; Doppler-limited widths 50-100 kHz; frequency accuracy <= 10 kHz) or its peak list, supplied by the user. It predicts catalogs with search windows derived from the declared prior accuracy, drives the human assignment loop (predict -> search -> pattern-match -> assign -> fit -> re-predict) with full quantum-number labelling (J K_a K_c, F for hyperfine, v_t/sigma or tunnelling-doublet labels), fits effective rotational Hamiltonians (Watson A/S, nuclear quadrupole, internal rotation and tunnelling doublets) to assigned lines by weighted least squares with a pinned SPFIT/SPCAT as the fit-of-record and export path, runs isotopologue and conformer campaigns, and exports SPFIT/SPCAT-compatible files, residual lists, refinement requests and publication tables with provenance. It is an interactive, stateful, project-based tool for a single workstation (Method Matrix Setup 2) or a CPU-only Codespace (Setup 1), hosted in BASE's Voila UI, with a secondary headless CLI for batch fits.
>
> **SpycFit IS:** microwave / CP-FTMW rotational assignment and fitting for the Method Matrix §2.1 system class (5-10 atom van der Waals and hydrogen-bonded complexes with at least one large-amplitude intermolecular coordinate, plus their monomers and isotopologues); effective-Hamiltonian fitting with SPFIT/SPCAT parity; hyperfine, internal-rotation, tunnelling-doublet, isotopologue, conformer and satellite campaigns; prediction windows from Product class; inertial-defect, planar-moment and Kraitchman/r_0 diagnostics (gated by fluxionality); Pickett I/O and round trip; residual-line bookkeeping; publication export; refinement-request authoring; the TORQ bundle consumer and its contract test.
>
> **SpycFit IS NOT:** electronic structure, geometry optimisation, VPT2, DVR or any quantum-chemistry output parsing (TORQ); conformer or topology search (TOPOS); UI hosting, scheduling, task queues, cross-module state ownership, network or air-gap security (BASE and deployment); IR, Raman, UV-Vis, TD-DFT, NMR, EPR or mass spectrometry; HITRAN/ExoMol line lists, 296 K reference scaling, pressure broadening or radiative transfer; mm-wave/THz or radio-astronomy catalogue production beyond 26 GHz; MLFF scouting or scout-anchor logic (TORQ §8A); inverse-inertia-tensor averaging of priors (Method Matrix §5.1, a TORQ job; consumed, not computed); Gaussian-process residual learning or any neural-network component; a daemon or writer of other modules' databases.
>
> **Lineshape decision.** SpycFit v2 contains no IR/Raman convolution. The only lineshape operation is a MHz-domain Gaussian/Voigt instrument function applied to its own rotational stick spectrum for overlay on the observed trace. IR/Raman stick rendering moves to TORQ reporting or a separate module; README §1-3 and User Manual §5.2.1/§5.4.1 (drop `Type = IR|Raman|UVVIS`, drop the PGOPHER-only claim) are rewritten in the same change so the four documents agree.

### 9.2 Definition of done per work package (GOV-14)

Reproduced from TORQ SRS §16 verbatim as the governing sentence: "Every work package must produce executable implementation, tests tied to requirements, migration notes for affected persisted data, and a measured evidence report. A checklist, source stub, hardcoded result, synthetic engine output or claimed agent audit cannot close a package."

A WP is done only when all of the following hold:
1. Changes are in `src/cochem_spycfit`, `tests/` and `docs/` only, submitted as a diff-based PR under about 1,500 changed lines (else split).
2. Every SHALL in the WP has at least one test carrying `@pytest.mark.req("SPYC-...")` that passes in CI on the full suite.
3. At least one acceptance test per WP compares a computed observable with a literature or pinned-SPCAT value whose tolerance was committed to `tests/acceptance/manifest.yaml` before the implementing PR (CI checks commit order).
4. Line coverage of touched files >= 85 %; no `src` function at 0 % coverage without a recorded justification.
5. `docs/evidence/WPnn.md` (<= 2 pages): what ran, where (host, versions), numbers vs tolerance, skipped or blocked items, open questions for the PI.
6. No edits to `pytest.ini`, CI workflows, `.gitignore`, linter config or dependency pins (those are PI-owned and change only in the hygiene PR or a dedicated PI-approved PR).
7. A migration note if `.par`/`.lin`/HDF5/FitSession schemas changed.
8. PI approval on the PR.

### 9.3 Artefact rules (GOV-15, REQ-02, GOV-10)

- `.gitignore` ignores run outputs by directory, never by scientific file extension; Pickett and HDF5 fixtures are committed under `tests/fixtures/<molecule>/` with `PROVENANCE.yaml` (DOI or CDMS/JPL tag; engine + version + input hash; or `parser-regression-only`). Fixtures without provenance may not be cited as physical evidence.

- Agent "audit" or "council" text, if produced at all, goes under `docs/agent_reports/` and is never cited as closing evidence.
- Agents modify code by patch/diff and never emit whole files; the "never truncate" directive is removed.

### 9.4 Anti-gaming rules: what to keep and drop (GOV-02, GOV-03, GOV-04, GOV-08, GOV-12, GOV-16, CRITIC-13)

**Keep (narrow hygiene):** tautological-assert check (`assert True`); sole-statement `pass`/`...` body check with ABC/Protocol/overload exemption; forbid `except ...: pass` and broad `except` without re-raise or log in `src/` (`verify_anti_patching.py`, run in CI).

**Drop:** the `np.zeros/ones/eye/empty/*_like` design rule (harmful; never implemented); BANNED_KEYWORDS and comment-pattern bans (gameable by construction, the arch spec itself evades them); the amnesty mechanism; the quota of "20 improvements"; BANNED_PARALLEL_IMPORTS (explicit PI decision; conflicts with the Method Matrix's Parsl pipeline); the "forbidden from verifying your own work" rule with no named verifier.

**Metrics that are informational only, never gates:** number of tests or LOC; pass counts from any testpaths subset; linter "0 violations"; absence of keywords; agent audit verdicts; checksums or byte counts of agent-produced files; provenance-tag counts; number of "improvements".
